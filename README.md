# ARTICLE — 公式サイト

Web制作・映像制作の2事業を軸にした静的サイトです。
記事（COLUMN / NEWS）と制作実績は **microCMS** で管理し、**Netlify** が自動でビルド・公開します。

---

## ⚠️ サイトを見るときは、必ずこのファイルから

> ### 🖱 `プレビュー起動_Mac.command`（Mac）
> ### 🖱 `プレビュー起動_Windows.bat`（Windows）
>
> **このどちらかをダブルクリック**してください。ブラウザが自動で開きます。
> 閉じるときは、いっしょに開いた黒い画面を閉じてください。

**`index.html` を直接ダブルクリックしないでください。**
文字だけの真っ白なページになります（下の画像のような状態）。壊れているわけではありません。

<details>
<summary>なぜそうなるのか（クリックで開きます）</summary>

このサイトはデザインファイルの場所を `/assets/style.css` と書いています。
先頭の `/` は「**サイトの一番上**」という意味です。

- Webサーバー経由（Netlify・上のプレビュー）… `サイトの一番上/assets/style.css` → **正しく見つかる**
- ファイルを直接ダブルクリック … `パソコンのドライブの一番上/assets/style.css` → **見つからない**

そのためデザイン・画像・動きがすべて読み込まれず、文字だけが並びます。
**Netlifyに公開すれば、この現象は起きません。**

この書き方にしているのは、`/column/記事名/` のような階層の深いページでも
同じ1行で書けるようにするためです。ページごとに `../../assets/…` と書き分ける必要がなくなります。

</details>

**Macで「開発元を確認できないため開けません」と出たとき**
`プレビュー起動_Mac.command` を **右クリック →「開く」→「開く」** を選んでください（初回のみ）。

**「Pythonが見つかりません」と出たとき**
[7章](#7-ローカルでのビルド確認方法)を参照してください。

## 1. まず知っておいてほしいこと

### 記事は「ビルド時」に埋め込まれます

このサイトは、**ブラウザからmicroCMSを呼び出していません。**
記事を公開すると Netlify がビルドを走らせ、記事本文がそのまま入ったHTMLファイルを作り直します。

```
microCMSで公開ボタン
  → Webhook が Netlify を叩く
  → Netlify が _build/build.py を実行
  → build.py が microCMS から記事を取得
  → 記事本文入りのHTMLを生成
  → 公開
```

この方式のメリットは3つです。

- **APIキーが外に出ない** — キーを使うのはビルド中のNetlifyサーバーだけです
- **表示が速い** — 開いた瞬間に本文が出ます。読み込み待ちがありません
- **検索エンジンに確実に読まれる** — HTMLに本文が入っているためです

### APIキーの扱い（重要）

microCMSのAPIキーは、**HTML・CSS・JavaScript・GitHubのどこにも書いていません。**
Netlifyの環境変数だけに登録します（手順は[6章](#6-呉屋さんが行う設定作業この順番で)）。

キーは必ず **GET のみ許可** で発行してください。書き込み権限は絶対に付けないでください。

## 2. 日常の記事更新（公開後の運用）

セットアップが終われば、記事の更新は次の操作だけで完了します。

| # | 操作 | 場所 |
|---|---|---|
| 1 | microCMS にログイン | https://app.microcms.io |
| 2 | 「記事（articles）」→「追加」 | microCMS管理画面 |
| 3 | タイトル・slug・本文などを入力 | 〃 |
| 4 | `category` で **COLUMN** か **NEWS** を選ぶ | 〃 |
| 5 | 「公開」ボタンを押す | 〃 |
| 6 | （自動）Netlifyがビルド。**1〜3分ほど**で公開されます | — |

サイト側で触る作業はありません。

**反映されないときは** Netlify管理画面の「Deploys」を開いてください。
`Published` になっていれば完了、`Failed` なら[12章](#12-困ったときは)を見てください。

### slug の付け方

`slug` はそのままURLになります（`/column/{slug}/`）。

- 使えるのは **半角英数字とハイフン** だけです（例：`web-renewal-tips`）
- 日本語・スペース・アンダースコアは使えません
- 他の記事と同じslugは使えません
- **一度公開したslugは変えないでください**（URLが変わり、リンクや検索結果が切れます）

ルール違反があるとビルドが止まり、Netlifyの画面に理由が日本語で出ます。
**その場合、公開中のサイトは前の状態のまま残る**ので、あわてなくて大丈夫です。

```
├── 404.html                            ← 〃

│   ├── content.py            ★文言はすべてこのファイルにあります
│   ├── cms.py                microCMSから取得・検証する処理
│   ├── preview.py            ローカルプレビュー用の簡易サーバー
│   └── sample-articles.json  ローカル確認用のサンプル記事
│
├── assets/
│   ├── style.css         全ページ共通のスタイル
│   ├── app.js            全ページ共通の動き
│   ├── ogp-default.png   SNSシェア用の共通画像（1200×630）
```

> 直接編集しても、次のビルドで消えます。修正は必ず `_build/` の中で行ってください。

| COLUMN | `/column/` | 記事一覧。ALL / COLUMN / NEWS で絞り込み |
| 記事詳細 | `/column/{slug}/` | NEWSの記事もこのURL形式です |
| CONTACT | `/contact/` | お問い合わせフォーム |

| 旧URL | 新URL | 扱い |
|---|---|---|

## 5. microCMS で作るAPIとフィールド

### 5-1. 新しく作るAPI：記事（エンドポイント `articles`）

microCMS管理画面 →「APIを作成」→ **リスト形式** を選択 →
エンドポイントに `articles` と入力（**この名前でないと動きません**）。

そのあと「APIスキーマ」で、次の9つのフィールドを作ります。

| フィールドID | 表示名 | 種類 | 必須 | 備考 |
|---|---|---|---|---|
| `title` | 記事タイトル | テキストフィールド | ○ | |
| `slug` | URL用文字列 | テキストフィールド | ○ | 半角英数字とハイフンのみ |
| `category` | カテゴリー | セレクトフィールド | ○ | 選択肢は `COLUMN` と `NEWS` の2つ。**単一選択**にしてください |
| `excerpt` | 記事の概要 | テキストエリア | | 一覧の説明文とSEO説明文に使われます。80〜120字が目安 |
| `content` | 記事本文 | リッチエディタ | ○ | |
| `eyecatch` | メイン画像 | 画像 | | 推奨 1600×1000 前後。未設定でもレイアウトは崩れません |
| `date` | 公開日 | 日時 | ○ | ここに入れた日付順（新しい順）で並びます |
| `seoTitle` | SEO用タイトル | テキストフィールド | | 空なら `{記事タイトル}｜ARTICLE` を自動生成 |
| `seoDescription` | SEO用説明文 | テキストエリア | | 空なら `excerpt` を使用 |

> **`category` の選択肢の作り方**
> セレクトフィールドを追加 →「選択肢」に `COLUMN` と入力してEnter → 続けて `NEWS` と入力してEnter。
> 大文字で入力してください。

**カテゴリーの使い分け**

- **COLUMN** … ホームページ制作、映像制作、SNS、地域企業向けのお役立ち記事
- **NEWS** … ARTICLEからのお知らせ、制作実績の公開、イベント情報、営業案内

### 5-2. すでにあるAPI（変更しないでください）

制作実績の2つは、エンドポイント名もフィールドも**そのまま**です。
取得のタイミングだけ「ブラウザ」→「ビルド時」に変わりました。

#### `works-web`（HP制作実績）

| フィールドID | 表示名 | 種類 | 備考 |
|---|---|---|---|
| `title` | サイト名（英字） | テキストフィールド | 例：WARM BLUE |
| `clientName` | クライアント名（日本語） | テキストフィールド | |
| `url` | サイトURL | テキストフィールド | PCではこのURLのプレビューが表示されます |
| `description` | 紹介文 | テキストエリア | |
| `tags` | タグ | テキストフィールド | カンマ区切り |
| `thumbnail` | サムネイル | 画像 | |
| `ghost` | 背景の大きな文字 | テキストフィールド | 未入力なら `title` |

#### `works-film`（映像制作実績）

| フィールドID | 表示名 | 種類 | 備考 |
|---|---|---|---|
| `title` | タイトル | テキストフィールド | |
| `category` | 種別 | テキストフィールド | 例：Social Film |
| `description` | 紹介文 | テキストエリア | |
| `thumbnail` | サムネイル | 画像 | |
| `video` | 動画ファイル | ファイル | mp4 |
| `url` | 外部リンク | テキストフィールド | 入れるとカード全体がリンクに |
| `vertical` | 縦型動画か | 真偽値 | 9:16 は ON |

**これらのAPIをまだ作っていない場合も、サイトは問題なく動きます。**
その間は `_build/content.py` に書いてある現在の実績（HP4件・映像5件）が表示されます。

> ### ⚠️ `thumbnail` は必ず設定してください
>
> **スマートフォンとタブレットでは、`thumbnail` に登録した画像がそのまま表示されます。**
> PCだけは実サイトのライブプレビュー（iframe）が上に重なりますが、スマホでは重い・
> 表示が崩れるなどの理由でiframeを読み込みません。
>
> `thumbnail` が空だと、スマホではサイト名だけのプレースホルダーになってしまいます。
> **サイトのトップページを撮ったスクリーンショット**（横長・幅1200px以上を推奨）を
> 登録してください。カード内では 16:10 で上端を基準に表示されます。

## 6. 呉屋さんが行う設定作業（この順番で）

ここから先は、**コード側では対応できない、管理画面での操作**です。
まだ何も実施していませんので、上から順に進めてください。所要は合計40〜60分ほどです。

---

### STEP 1 — microCMS で `articles` API を作る

1. https://app.microcms.io にログイン
2. 左メニューの一番下「**APIを作成**」をクリック
3. 「**自分で決める**」を選択
4. API名：`記事`／エンドポイント：`articles` と入力して「次へ」
5. 「**リスト形式**」を選択して「次へ」
6. 仮のフィールドが出るので、そのまま「作成」
7. できたAPIを開き、右上の「**API設定**」→「**APIスキーマ**」
8. [5-1の表](#5-1-新しく作るapiエンドポイント-articles)のとおりに9つのフィールドを追加して「変更を反映」

---

### STEP 2 — microCMS で APIキーを発行する

1. 左下の「**サービス設定**」→「**APIキー**」
2. 「**APIキーを作成**」
3. 名前は `netlify-build` など分かるものに
4. **権限の設定で、GET だけを ON にします。**
   POST / PUT / PATCH / DELETE は**すべてOFF**のままにしてください
5. 作成後に表示されるキーをコピーして、**一時的にメモ帳などに控えます**
   （STEP 5 でNetlifyに貼り付けます。貼り終わったらメモは消してください）

あわせて、画面上部のURL `https://○○○○.microcms.io` の **○○○○ の部分**も控えておきます。
これが「サービスドメイン」です。

---

### STEP 3 — GitHub にアップロードする

1. https://github.com にログイン（アカウントがなければ作成）
2. 右上の「**+**」→「**New repository**」
3. Repository name：`article-site` など
4. **Private**（非公開）を選択 →「Create repository」
5. 次の画面の「**uploading an existing file**」というリンクをクリック
6. `article-site` フォルダの**中身**（`index.html` や `assets` や `_build` など）を
   まとめてドラッグ＆ドロップ
   - ※ `article-site` フォルダごとではなく、**中身**をアップロードしてください
   - ※ `assets/hero-final.mp4` が14MBあります。1ファイル25MBまでなので大丈夫ですが、
     アップロードに数分かかることがあります
7. 下の「**Commit changes**」をクリック

---

### STEP 4 — GitHub と Netlify をつなぐ

1. https://app.netlify.com にログイン
2. 「**Add new site**」→「**Import an existing project**」
3. 「**Deploy with GitHub**」を選び、GitHubの認証を許可
4. さきほど作ったリポジトリ（`article-site`）を選択
5. ビルド設定の画面が出ます。**次の内容になっているか確認**してください
   （`netlify.toml` を同梱しているので、自動で入っているはずです）

   | 項目 | 値 |
   |---|---|
   | Build command | `python3 _build/build.py` |
   | Publish directory | `.` |

6. **まだ「Deploy」を押さないでください。**
   同じ画面の「**Add environment variables**」を開いて、STEP 5 に進みます

---

### STEP 5 — Netlify に環境変数を登録する

登録する場所：**Site configuration → Environment variables → Add a variable**
（STEP 4 の画面から続けて登録してもOKです）

次の3つを登録します。

| Key | Value | 備考 |
|---|---|---|
| `MICROCMS_SERVICE_DOMAIN` | STEP 2 で控えた ○○○○ | `https://` や `.microcms.io` は含めません |
| `MICROCMS_API_KEY` | STEP 2 で控えたAPIキー | GET専用のキー |
| `SITE_URL` | `https://article58.jp` | 末尾のスラッシュは付けません |

> `SITE_URL` を登録しない場合は `https://article58.jp` が自動で使われます。
> ただし、独自ドメインを別のものにする場合は必ず登録してください。
> （sitemap.xml・canonical・OGPのURLがすべてここを基準に作られます）

登録できたら「**Deploy site**」を押します。
「Deploys」タブで `Published` になれば成功です。

---

### STEP 6 — Netlify で Build Hook を発行する

「記事を公開したら自動でビルドする」ための呼び出し口を作ります。

1. Netlify管理画面 →「**Site configuration**」
2. 左メニュー「**Build & deploy**」→「**Continuous deployment**」
3. 下のほうにある「**Build hooks**」→「**Add build hook**」
4. Build hook name：`microcms` と入力
5. Branch to build：`main`（GitHubの初期ブランチ名。`master` の場合はそちら）
6. 「**Save**」
7. 表示される `https://api.netlify.com/build_hooks/xxxxxxxxxxxx` という
   **URLをコピー**します

---

### STEP 7 — microCMS に Webhook を登録する

1. microCMS管理画面で、**`articles` API** を開く
2. 右上「**API設定**」→ 左メニュー「**Webhook**」
3. 「**追加**」→ サービス一覧から「**Netlify**」を選択
4. 識別名：`Netlify 自動デプロイ`
5. **Build Hook URL** に、STEP 6 でコピーしたURLを貼り付け
6. 「通知タイミング」で、少なくとも次にチェックを入れます
   - コンテンツの**公開**時
   - コンテンツの**公開が終了**した時（＝非公開にしたとき）
   - コンテンツの**削除**時
7. 「設定する」

**同じ設定を `works-web` と `works-film` にも行ってください。**
実績を更新したときも自動で反映されるようになります。

**動作確認**：microCMSで記事をひとつ公開 → Netlifyの「Deploys」に新しいビルドが
自動で始まればOKです。

---

### STEP 8 — 独自ドメイン（article58.jp）を設定する

1. Netlify管理画面 →「**Domain management**」→「**Add a domain**」
2. `article58.jp` を入力して「Verify」→「Add domain」
3. Netlifyが表示するネームサーバー、または DNSレコードを、
   **ドメインを取得した会社の管理画面**（お名前.com、ムームードメイン等）に設定します
   - 方法A（おすすめ）：Netlify DNS を使う → Netlifyが表示する4つのネームサーバーを
     ドメイン会社側に設定
   - 方法B：いまのDNSのまま使う → `article58.jp` に `A` レコード `75.2.60.5`、
     `www` に `CNAME` で Netlifyのサイト名（`○○.netlify.app`）を設定
4. 反映まで数分〜48時間かかります
5. 反映後、Netlifyの「**HTTPS**」欄で「**Verify DNS configuration**」→
   証明書（Let's Encrypt）が自動発行されます
6. 「**Force HTTPS**」を ON にします

ドメインが `article58.jp` 以外になった場合は、**STEP 5 の `SITE_URL` を必ず変更**して
再デプロイしてください。

### STEP 9 — お問い合わせのメール通知を設定する

## 7. ローカルでのビルド・確認方法

### 必要なもの

Python 3.8以上だけです。追加のインストール（pip等）は不要です。

- **Mac** … 最初から入っています。入っていなければターミナルで `xcode-select --install`
- **Windows** … https://www.python.org/downloads/ からインストール。
  このとき「**Add python.exe to PATH**」のチェックを**必ず入れてください**

### 方法A：ダブルクリックで見るだけ（おすすめ）

| OS | ダブルクリックするファイル |
|---|---|
| Mac | `プレビュー起動_Mac.command` |
| Windows | `プレビュー起動_Windows.bat` |

ブラウザが自動で開きます。終了するときは、いっしょに開いた黒い画面を閉じてください。

- 空いているポートを自動で選ぶので、ポート番号を気にする必要はありません
- キャッシュを無効にしているので、修正したら**普通のリロードだけで反映**されます

> 文字だけのページになります。理由はこのREADMEの冒頭を見てください。

### 方法B：文言や実装を直したあと（コマンド）

```bash
# 2. プレビューする（方法Aのダブルクリックと同じことをします）
python3 _build/preview.py
```

`python3 -m http.server 8000` でも確認できます（その場合は `http://localhost:8000`）。

### microCMS の設定がない状態での動作

## 9. お問い合わせフォーム（設定済み）

**Netlify Forms への接続は実装済みです。** サイト側で追加のコード作業はありません。
残っているのは、Netlify管理画面での**メール通知の設定だけ**です（下の 9-2）。

### 9-1. いまの仕組み

```
フォーム送信
  → Netlify が受け取り、管理画面の「Forms」に保存
  → 送信者は /thanks/（送信完了ページ）へ移動
```

実装している内容は次のとおりです。

| 項目 | 内容 |
|---|---|
| フォーム名 | `contact`（Netlify管理画面での表示名） |
| 送信後の遷移先 | `/thanks/` |
| スパム対策 | honeypot（`bot-field`）。人には見えない項目で、入力があれば送信しません |
| 必須項目 | お名前 / メールアドレス / ご相談内容 |
| 二重送信対策 | 送信中はボタンを無効化し「送信中…」に変わります |
| 送信される項目 | 種別（Web/映像/両方/その他）・お名前・会社名・メール・電話・ご相談内容 |

生成元は `_build/build.py` の `page_contact()` にあります。
再ビルドしても設定は消えません。

> **フォームの項目を増やしたとき**は、`_build/build.py` に `<input>` を追加して
> 再ビルドし、GitHubへ反映してください。Netlifyが次のデプロイで自動的に認識します。
> （Netlifyはデプロイ時に静的HTMLを解析してフォームを登録する仕組みのため、
> JavaScriptで後から追加した項目は認識されません）

### 9-2. ⚠️ Netlify管理画面での作業：メール通知の設定

**これをしないと、問い合わせが来てもメールが届きません。**
（管理画面の「Forms」には溜まりますが、気づけません）

1. サイトを一度Netlifyにデプロイします
2. Netlify管理画面 →「**Forms**」を開きます
   - `contact` というフォームが表示されていれば、検出成功です
   - 表示されない場合は、[12章](#12-困ったときは)を確認してください
3. 「**Settings and usage**」→「**Form notifications**」→「**Add notification**」
4. 「**Email notification**」を選択
5. 入力します

   | 項目 | 入力内容 |
   |---|---|
   | Event to listen for | `New form submission` |
   | Email to notify | 受信したいメールアドレス |
   | Form | `contact` |

6. 「**Save**」

これで、問い合わせがあるたびにメールが届きます。
迷惑メールに入ることがあるので、テスト送信して受信を確認してください。

### 9-3. テスト方法

公開後、実際のサイトのお問い合わせフォームから1件送信してください。

- `/thanks/` に移動すれば送信成功です
- Netlify →「Forms」→ `contact` に内容が記録されます
- 設定したアドレスにメールが届きます

> ローカルプレビューでは送信できません（Netlify上でのみ動作します）。
> ローカルで押すと `/thanks/` が表示されますが、データは保存されません。

### 9-4. 迷惑メールが増えたら

Netlifyには honeypot のほかに reCAPTCHA も用意されています。
必要になったら、`_build/build.py` のフォームに `data-netlify-recaptcha="true"` と
`<div data-netlify-recaptcha="true"></div>` を追加してください。

- **mp4（H.264）の再生**（確認環境のブラウザがH.264に対応していないため、
  再生・停止のロジックは別形式の動画で検証しています。実際のブラウザでは問題なく再生されます）
- **Webhook → 自動デプロイの一連の流れ**
- **Google Fonts の表示**（この環境では外部通信が遮断されており、代替フォントで確認しています。
  実際のサイトではAnton / Noto Sans JP / Inter が読み込まれます）

## 12.4 余白（左右のマージン）の調整

サイト全体の左右の余白は、CSSの変数 **`--pad`** ひとつで決まっています。
`assets/style.css` の先頭付近と、末尾の「WIDE SCREEN」の項にあります。

| 画面幅 | 左右の余白 |
|---|---|
| 375px（スマホ） | 20px |
| 768px（タブレット） | 26px |
| 1024px | 35px |
| 1440px | 81px |
| 1920px | 133px |
| 2200px以上 | 140px（上限） |

1024px未満は従来どおりです。1024px以上で画面幅に応じて広がり、
1024pxちょうどの値が従来値と一致するようにしてあるので、
ウインドウ幅を変えても余白がガクッと飛びません。

**もっと広く／狭くしたいとき**は、`assets/style.css` 末尾の次の行を変えてください。

```css
@media (min-width:1024px){
  :root{
    --pad:min(calc(34.8px + (100vw - 1024px) * 0.11), 140px);
    /*                                          ↑広がり方   ↑上限 */
  }
}
```

- `0.11` を大きくすると、画面が広いほど余白が増えます
- `140px` が余白の上限です

## 12.5 WORKSページの仕組み

### タブとページ送り

WORKSページは **WEB / FILM のタブ** で切り替わります。初期表示はWEBです。

- 1ページに表示するのは **最大9件**。10件目からは次のページになります
- 表示中の状態はURLに反映されます（例：`/works/?type=film&page=2`）
- ブラウザの戻る・進むでタブとページ番号が復元されます
- タブを切り替えると1ページ目に戻ります
- SERVICEページの「映像制作実績を見る」（`/works/#film`）はFILMタブが開きます

**件数を9件から変えたいとき**は `_build/build.py` の先頭近くにある
`PER_PAGE = 9` を書き換えて再ビルドしてください。

> 実績データは**全件がHTMLに書き出されています**。JavaScriptは表示・非表示を
> 切り替えているだけなので、検索エンジンは10件目以降も読み取れます。

### 端末によるサムネイルの出し分け

| 端末 | 表示されるもの |
|---|---|
| PC（マウス操作） | `thumbnail` の画像 → スクロールすると実サイトのライブプレビューが重なる |
| スマホ・タブレット | `thumbnail` の画像（iframeは作りません） |
| `thumbnail` が未設定 | サイト名のプレースホルダー |

サムネイルは常に `<img>` として出力しているので、通信環境やJavaScriptの状態に
左右されずに表示されます。

### 映像の再生

FILMタブのカードを押すと、**モーダル（拡大表示）で再生**されます。

- 閉じるボタン / 背景クリック / Escキー のどれでも閉じられます
- 閉じると再生が止まり、読み込みも解除されます
- 同時に2本以上再生されることはありません
- 画面外の動画は読み込みません（`preload="none"`）
- 縦型動画（`vertical` を ON）は 9:16、横型は 16:9 で表示されます

microCMSの `works-film` の設定による動作の違いは次のとおりです。

| 設定 | 動作 |
|---|---|
| `video` あり | モーダルで動画を再生 |
| `url` のみ | 外部ページを別タブで開く |
| `thumbnail` のみ | 画像カードとして表示（クリック動作なし） |

## 12. 困ったときは

### ビルドが失敗する（Netlifyで `Failed`）

Netlify →「Deploys」→ 失敗したビルドをクリック → ログを一番下まで見てください。

| ログの内容 | 原因と対処 |
|---|---|
| `slug「…」が重複しています` | microCMSで片方のslugを変更してください |
| `slug「…」は使えません` | 半角英数字とハイフンだけに直してください |
| `title（記事タイトル）が空です` | microCMSで入力してください |
| `category が未選択です` | COLUMN か NEWS を選んでください |
| `HTTP 401` / `HTTP 403` | `MICROCMS_API_KEY` が間違っているか、GET権限がありません |
| `HTTP 404` + `articles` | エンドポイント名が `articles` になっているか確認してください |
| `python3: command not found` | `netlify.toml` の `PYTHON_VERSION` の行を削除して再デプロイ |

### スマホでHP実績のサムネイルが出ない

microCMSの `works-web` で **`thumbnail` が未設定**です。画像を登録して再公開してください。
PCではライブプレビューが出るため気づきにくいので、スマホでも確認してください。

**ビルドが失敗しても、公開中のサイトは前の状態のまま**です。サイトが落ちることはありません。

### 記事を公開したのに反映されない

1. Netlify →「Deploys」に新しいビルドが始まっているか確認
   - 始まっていない → microCMSのWebhook設定（STEP 7）を見直してください
   - 失敗している → 上の表を確認してください
2. ビルドは成功しているのに古い内容 → ブラウザのスーパーリロード
   （Windows: `Ctrl+Shift+R` / Mac: `Cmd+Shift+R`）

### 記事を削除・非公開にしたのにページが残る

`build.py` は毎回 `column/` フォルダを作り直すので、通常は残りません。
残る場合はWebhookの「削除時」「公開終了時」にチェックが入っているか確認し、
Netlifyで「Trigger deploy → **Clear cache and deploy site**」を実行してください。

### 補足：未使用素材について

`assets/_source/` に、サイト内で直接使っていないロゴ素材を残しています
（`ARTICLE-logo-original.png` / `wordmark-white.png`）。
`wordmark-white.png` は `assets/ogp-default.png` の生成に使いました。
今後の印刷物などで使う可能性を考えて同梱していますが、不要であれば削除して問題ありません。
